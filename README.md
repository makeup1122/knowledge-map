# 知识地图

山西及中国北方历史地理知识地图。纯静态单页（Leaflet），无需后端、无需 API key。

- 线上地址：<https://makeup1122.github.io/knowledge-map/>
- 本地使用：直接用浏览器打开 `index.html`，或在仓库目录运行 `python3 -m http.server 8766` 后访问 `http://127.0.0.1:8766/`

## 功能概览

- **左侧面板**：顶部搜索；「筛选」里是主题标签和示意路线；「管理」里是加点、导入/导出 JSON、恢复种子。
- **列表跟着地图走**：默认只列出当前视野内的点，按分区折叠；搜索或选标签时跨视野列出所有匹配点。可切换「只看当前视野 / 全部」。
- **标记显示规则**：默认不显示标记；选了标签、搜索、勾选路线、点开某个点，或放大到 8 级及以上时，才显示相关标记。
- **二级详情**：点击地点后在左侧面板展开（史料状态、概述、详细介绍、地理/怎么走、出行提示、照片、坐标），带「← 返回」。
- **手机**：面板变成底部上拉抽屉，点把手在约 30% / 75% 高度之间切换。
- **图层**（右上角）：底图有 OSM 标准、OpenTopoMap 地形/等高线、卫星影像（Esri）；叠加层有河网、铁路（两者都是从 OSM 实时抽取，需放大到一定级别）、山体阴影、地名与边界。

## 文件结构

| 文件 | 说明 |
| --- | --- |
| `index.html` | 全部页面、样式和逻辑；种子数据 `SEED_POINTS` / `SEED_ROUTES` 和分区 `REGION_ORDER` / `REGION_MAP` 都内嵌在这里 |
| `all-points-v3.json` | 种子数据的 JSON 副本（`{points, routes}`），可用页面里的「导入 JSON」载入 |
| `lf/` | 本地自带的 Leaflet 1.9.4（避免依赖外部 CDN） |

## 数据格式

### 知识点（point）

```json
{
  "id": "sx_03",
  "title": "雁门关",
  "era": "战国至明清 · 长城要塞",
  "desc": "一两句话简述，显示在列表和弹窗里",
  "detail": "二级详情正文，可分段",
  "geo_notes": "地理 / 怎么走",
  "visit_tips": "出行提示",
  "source": "出处说明",
  "verified": true,
  "tags": ["明长城", "晋北防线"],
  "region": "晋北",
  "photos": ["https://..."],
  "lat": 39.179352,
  "lng": 112.875901
}
```

- `id` 必须唯一。约定前缀：`sx_` 山西起点、`bt_` 豆包包头线、`dest_` 出行预读目的地；新点可自拟前缀，但不要和已有的重复。
- `verified: false` 会在列表和详情里标「待核实」，来自 AI 对话或未核实资料的点一律设为 `false` 并在 `source` 写明来源。
- `tags` 决定「筛选」里出现哪些主题标签，尽量复用已有标签，不要随意新造近义词。

### 示意路线（route）

```json
{
  "id": "route_waisanguan",
  "title": "外三关西线（偏头—宁武—雁门）",
  "tags": ["明长城"],
  "note": "示意连线，非精确走向",
  "point_ids": ["bt_03", "bt_04", "bt_08", "sx_03"]
}
```

`point_ids` 按顺序引用已有知识点的 `id`，地图上按顺序连成虚线。

## ⚠️ 坐标与分区规矩（所有人、所有 agent 都要遵守）

1. **经纬度一律用国际通用的 WGS-84**。从高德、腾讯地图等国内地图拷来的坐标是 GCJ-02（会偏几百米），**必须先转换成 WGS-84 再填**。百度地图是 BD-09，同样要转换。
2. **每个新点都要填分区**，只能用下面六个已有分区名之一（写在点的 `region` 字段，或加进 `index.html` 的 `REGION_MAP`）：
   - 晋北
   - 晋中
   - 晋南
   - 晋东南
   - 内蒙古南部（土默川—岱海）
   - 豫西北（黄河中游）

   放不进这六个分区的，先问「地理」再定，不要自己新建分区名。

## 修改流程

1. 改动先在本地预览测试（`python3 -m http.server 8766`），确认没问题再推送；用户要求先测后推。
2. 改完 `index.html` 后，至少把最后一个 `<script>` 块抽出来跑一次 `node --check`，避免语法错误导致整页白屏。
3. 更新种子数据时，同时更新 `index.html` 里的 `SEED_POINTS` / `SEED_ROUTES` 和 `all-points-v3.json`，保持一致。
4. 浏览器会把数据存在本地（localStorage），改了种子之后需要在页面「管理 → 恢复种子」才能看到新种子（会覆盖本地已加的点，先「导出 JSON」备份）。
5. 推送到 `main` 分支后，GitHub Pages 一般一两分钟内更新。
